
# Phase 726 — Artifact Intelligence Foundation

## Purpose

Phase 726 begins controlled artifact-intelligence evolution from the stable Phase 725 visual refinement baseline.

The goal is to move artifact understanding, semantic structure, and visual composition authority gradually toward worker-authored artifact payloads while preserving all runtime-critical contracts.

## Non-Negotiable Stability Rules

- Do not mutate retry architecture.

- Do not mutate SSE contracts.

- Do not mutate task polling contracts.

- Do not mutate database schema.

- Do not remove markdown fallback persistence.

- Do not replace the existing artifact preview route.

- Do not introduce speculative rendering infrastructure.

- Do not layer fixes after repeated failed attempts.

## Phase 726 Direction

Phase 726 should proceed in additive layers only:

1. Define semantic artifact schema.

2. Define visual artifact metadata boundaries.

3. Add worker-side semantic classification helpers.

4. Add worker-side visual composition helpers.

5. Keep renderer compatibility intact.

6. Validate each step in Docker/browser before advancing.

## Artifact Intelligence Goals

- Worker-authored semantic intent.

- Worker-authored artifact sections.

- Worker-authored visual composition metadata.

- Reduced renderer-derived interpretation.

- Preserved markdown fallback.

- Future preview-aware advisory loop readiness.

## Explicitly Deferred

The following are not part of the first Phase 726 pass:

- Database migrations.

- Route replacement.

- Preview modal redesign.

- Retry contract changes.

- SSE event shape changes.

- Full Matilda preview-awareness.

- Native artifact editor controls.

- Render-native artifact export pipeline.

## Safe First Implementation Target

The first safe implementation target is a schema-only and helper-only foundation.

No existing runtime path should depend on the new schema until the schema is validated and helper output is inspected safely.
