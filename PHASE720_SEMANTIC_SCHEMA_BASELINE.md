
# Phase 720: Semantic Artifact Schema Baseline

## Purpose

Begin Phase 720 from the sealed Phase 719 semantic artifact visibility baseline.

Phase 720 must focus on worker-authored semantic enrichment through a contract-first corridor, without destabilizing the current frontend-derived semantic rendering path.

## Authoritative Starting Point

- Phase 719 semantic artifact visibility baseline is stable.

- Inline semantic rendering is authoritative.

- iframe/srcdoc rendering corridor remains retired from active runtime paths.

- Artifact preview route is operational.

- Shared artifact volume is verified.

- Retry architecture is preserved.

- SSE propagation is preserved.

- Agent Pool refresh persistence is verified.

- Dashboard rebuild workflow is verified.

## Phase 720 Initial Boundary

Allowed:

- Inspect worker artifact generation path.

- Inspect current markdown artifact persistence format.

- Inspect frontend semantic parser expectations.

- Draft semantic schema proposal in documentation first.

- Add compatibility-preserving semantic metadata only after inspection.

Not allowed initially:

- No DB schema mutations.

- No retry contract mutations.

- No SSE contract mutations.

- No routing contract mutations.

- No removal of existing markdown artifact behavior.

- No iframe/srcdoc corridor reactivation.

- No speculative renderer complexity.

## Contract-First Goal

Define a worker-authored semantic artifact payload that can eventually include:

- artifact_kind

- semantic_version

- task_summary

- execution_plan

- actionable_outputs

- evidence_notes

- operator_next_steps

- raw_markdown_fallback

## Compatibility Requirement

The current enriched markdown artifact must remain the fallback and must continue rendering correctly through the existing inline semantic renderer.

Any future semantic payload must be additive, not replacing the existing artifact path until browser-validated.

## Protocol Enforcement

- One hypothesis per cycle.

- Inspect before mutation.

- Preserve stable runtime first.

- Maximum three failed attempts per hypothesis.

- Revert immediately if the failure does not clearly indicate the next step.

- Archive before runtime contract changes.
