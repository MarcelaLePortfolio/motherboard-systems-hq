
# Phase 732 Advisory Preview Overlay Containment

## Status

Phase 732 advisory Preview overlay containment model established.

This document defines the containment rules for any future semantic Preview overlay systems operating within the observability-only corridor.

## Objective

Allow richer semantic inspection overlays while preserving:

- renderer authority

- Preview authority

- markdown authority

- runtime isolation

- orchestration isolation

- rollback integrity

- DR integrity

## Core Principle

Preview overlays may observe.

Preview overlays may not control.

All semantic overlays must remain advisory-only and non-authoritative.

## Overlay Definition

An advisory Preview overlay is defined as:

- additive semantic inspection data

- non-authoritative visual annotation

- removable Preview-adjacent metadata

- renderer-independent semantic observation

Overlays may exist beside Preview.

Overlays may never become Preview authority.

## Allowed Overlay Behaviors

Permitted behaviors include:

- semantic section annotations

- semantic density indicators

- readability advisory markers

- semantic drift indicators

- composition manifests

- semantic snapshot comparison markers

- advisory semantic summaries

These behaviors must remain:

- observational

- reversible

- removable

- renderer-contained

- Preview-contained

## Forbidden Overlay Behaviors

### Renderer Authority Violations

Forbidden examples:

- semantic-driven layout mutation

- semantic render prioritization

- semantic visual restructuring

- semantic display suppression

- semantic component injection

### Preview Authority Violations

Forbidden examples:

- Preview flow control

- semantic Preview orchestration

- semantic Preview mutation

- semantic Preview replacement

- semantic Preview override behavior

### Runtime Authority Violations

Forbidden examples:

- semantic execution weighting

- semantic orchestration coupling

- semantic retry decisions

- semantic routing behavior

- semantic adaptive execution

### Persistence Authority Violations

Forbidden examples:

- semantic-required storage state

- semantic persistence enforcement

- semantic canonicalization

- semantic schema authority

## Overlay Isolation Guarantees

All semantic overlays must remain:

- additive

- advisory-only

- non-authoritative

- renderer-isolated

- Preview-isolated

- markdown-fallback-safe

- rollback-safe

- DR-safe

- assertion-compatible

## Overlay Rendering Constraints

Overlays may:

- visually annotate

- summarize

- inspect

- compare

- highlight

- diagnose

Overlays may never:

- reorder

- mutate

- suppress

- transform

- orchestrate

- execute

## Deterministic Overlay Requirements

Overlay systems must remain:

- deterministic

- reproducible

- removable

- snapshot-safe

- rollback-compatible

- regression-testable

Overlay systems may never:

- self-modify

- auto-adapt

- rewrite Preview state

- mutate renderer state

- mutate runtime behavior

## Recovery Discipline

If overlay systems cross containment boundaries:

1. revert immediately

2. restore last stable checkpoint

3. isolate authority leak

4. preserve rollback integrity

5. avoid speculative layered fixes

6. re-enter through additive observability-only containment

Phase 732 advisory Preview overlays succeed only if:

- semantic inspection becomes richer,

- overlays remain observational,

- renderer authority remains preserved,

- Preview authority remains preserved,

- runtime behavior remains unchanged,

- persistence behavior remains unchanged,
